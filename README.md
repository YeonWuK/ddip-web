# DDIP Web

**DDIP**은 크라우드펀딩(프로젝트 모금)과 **실시간 경매**를 한 서비스에서 제공하는 플랫폼입니다. 본 저장소는 그중 **웹 프론트엔드**를 담당하며, 사용자·창작자·관리자가 실제 업무 흐름으로 이용할 수 있도록 화면·상태·API 연동을 구현했습니다.

|------|------|
| 소스 코드 | [YeonnWooo/ddip-web — `front_setup`](https://github.com/YeonnWooo/ddip-web/tree/front_setup) |

---

## 서비스 한눈에

- **크라우드펀딩**: 프로젝트를 등록하고 리워드(티어)를 구성한 뒤, 후원자가 금액을 모으며 목표 달성까지 진행 상태를 확인합니다.
- **경매**: 경매를 등록·수정하고, 참여자는 입찰·내역 조회를 하며 필요 시 **실시간 입찰 반영**(WebSocket/STOMP)을 사용합니다.
- **운영**: 관리자는 사용자·프로젝트·경매를 검토하고 승인·거절 등 조치를 할 수 있습니다.

백엔드 REST API, 이미지(S3), 인증 토큰과 연동하는 구조입니다.

## 주요 기능 (전체)

### 메인·공통

- **메인 홈**: 인기 프로젝트·경매, 마감 임박 콘텐츠 큐레이션, 히어로 배너(검색·카테고리·통계·CTA)
- **글로벌 내비게이션**: 로고, 주요 메뉴, 검색, 알림·찜·프로필 진입
- **빈 상태(Empty State)**: 데이터 없음·검색 결과 없음·필터 불일치 등 상황별 안내와 다음 행동 유도
- **에러·로딩 경계**: App Router 기준 전역 및 프로젝트·경매 **상세 세그먼트**별 `error.tsx`·`loading.tsx`, 재시도·목록 복귀 등 복구 UX
- **SEO·공유**: 목록·검색 등 **정적 metadata**, 프로젝트·경매 **상세는 `generateMetadata`**로 제목·설명·Open Graph 이미지 반영(검색·SNS 미리보기)

### 인증·계정

- **이메일 로그인·회원가입·로그아웃**
- **OAuth**: 콜백 처리 후 토큰·사용자 정보 반영 (`/oauth/callback` 등)
- **OAuth 이후 프로필 완성**: 이름·닉네임·전화 등 필수 정보 보완 화면
- **보호 라우트**: 미로그인 시 로그인 페이지로 유도
- **토큰 관리**: Access·Refresh 저장 및 만료 시 갱신·재요청 흐름(401 기준, 세션 만료 시 일관 로그아웃)

### 크라우드펀딩(프로젝트)

- **목록**: 전체 프로젝트 페이지, **무한 스크롤**(Intersection Observer, 미리 로드 여유)
- **필터·정렬**: 진행 상태(전체·진행·성공·실패·취소 등), 정렬(최신·인기·마감 임박·모금액 등) — **Zustand + localStorage**로 새로고침 후에도 유지
- **상세**: 프로젝트 소개·리워드·후원(펀딩) 참여
- **생성·수정**: 멀티파트 폼, **Zod 검증**, 이미지 **단일·다중 업로드**(FormData, S3)
- **리워드 티어**: 티어 카드·티어 입력 폼
- **후원(펀딩)**: 리워드 선택 후 후원 요청, **내 후원 내역** 조회
- **배송지**: 후원 시 **다음 우편번호 검색**(Daum 우편번호) 연동
- **찜하기**: 프로젝트 카드 하트, 위시리스트 저장
- **상태 표시**: 실패·취소·일시정지 등 운영 상태에 맞는 배지·구분 UI

### 경매

- **목록**: 전체 경매 페이지, **무한 스크롤**
- **필터·정렬**: 경매 상태(예정·진행·종료·취소 등), 정렬(최신·가격·마감 임박·입찰 수 등)
- **상세**: 현재가·입찰 UI·입찰 내역, **실시간 입찰 목록** 컴포넌트(WebSocket 훅과 연계)
- **생성·수정**: 멀티파트·이미지·검증
- **입찰**: 입찰 요청, **내 입찰 내역**, 경매별 입찰 내역 조회
- **찜하기·알림**: 경매 카드 찜, **찜한 경매 모니터링**(전역), 시작·종료 등 알림·중복 방지·가시성(탭 포커스) 고려
- **검색 연동**: 통합 검색에서 경매 검색 API 사용

### 검색

- **통합 검색 페이지**: 프로젝트·경매를 한 화면에서 검색
- **필터·정렬**: 목록 페이지와 동일한 필터 스토어 연동
- **빈 결과·복구**: 일부 검색 소스 실패 시에도 가능한 결과 표시 등 회복력 고려

### 마이페이지

탭으로 구성된 **내 활동 허브**:

1. **내 프로젝트** — 내가 만든 펀딩 목록  
2. **내 경매** — 내가 연 경매 목록  
3. **후원 내역** — 후원한 프로젝트  
4. **입찰 내역** — 입찰한 경매  
5. **찜한 항목** — 찜한 프로젝트·경매  

URL 쿼리로 특정 탭(예: 찜한 항목) 진입 지원.

### 관리자

- **관리자 전용 페이지**: 사용자·프로젝트·경매를 **탭**으로 구분
- **승인·거절 등 운영 액션**: 모달·사유 입력 등 워크플로우
- **관리자 API 연동**: 사용자·프로젝트·경매 목록 및 조치

### 데이터·화면 품질

- **금액·날짜**: 만원·억 단위 등 가독성 포맷, 날짜 파싱·검증(잘못된 날짜 표시 방지)
- **권한**: 프로젝트·경매 수정 등 권한에 따른 UI 제어
- **이미지**: S3 키를 풀 URL로 변환해 표시, 업로드 실패·플레이스홀더 처리
- **API 레이어**: 크라우드·경매·사용자·인증·배송지·관리자·검색 등 **도메인별 서비스 모듈**로 분리, 중앙 허브에서 re-export
- **타입**: OpenAPI(Swagger) 기반 **`openapi-typescript`**로 생성 타입과 수동 타입 병행

## 구현에서 강조한 점

1. **유지보수**: 단일 대형 API 파일을 도메인 단위로 나누고, 허브 파일은 **재export 중심의 얇은 레이어**로 유지해 변경 범위를 줄였습니다.  
2. **인증 UX**: 토큰 만료·갱신·재시도·세션 종료를 **HTTP 클라이언트와 인증 Context**로 나누어, 끊김 없는 이용과 명확한 로그아웃을 병행했습니다.  
3. **검색·폼 반응성**: 여러 검색 호출의 **부분 실패 허용**, 수량·금액 계산이 무거운 입력은 **지연된 파생 값**으로 분리해 체감 속도를 개선했습니다.  
4. **운영·품질**: 관리자 모달 상태를 **일관된 초기화 규칙**으로 묶어, 조치 후 화면이 멈추는 문제를 방지했습니다.

## 엔지니어링 성과 (코드 구조)

- API 진입점을 **단일 초대형 파일에서 도메인 분리 + 약 74줄 규모의 허브**로 재구성해, 읽기·검색·리뷰 비용을 크게 줄였습니다.

```bash
cd front
```
